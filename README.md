# task-dispatch · 任务分拣器 🧭 v1.11

> 让 AI 助手决定**对齐颗粒度**：这个任务该拷问到多细，然后调用对应流程执行。

用 AI 干活，最烦两种事：改个标题它问东问西 😤，做个系统它又闷头乱干 😵。task-dispatch 让助手自己看人下菜——**你只管说要什么，它自己掂量该对齐多少、怎么干。**

## ✨ 核心哲学

> **没有真正的清晰，只有不同程度的模糊。拷问是第一动作，永远发生；材料只决定拷问的对象和深度。**

用户说"想清楚了/都定好了"往往只是口头状态，细节一定存在未对齐的部分。task-dispatch 的价值就是判断这个任务**该拷问到多细**，然后执行对应颗粒度的对齐。

## 🎯 四档判断

判断依据两个信号：任务大小（改小地方/写一份东西/建一整套/说不清）+ 材料完备度（三态）：

| 大小 | 材料 | 走法 |
|---|---|---|
| 🔧 改个小地方 | — | 直接做，一句复述确认，零流程语言 |
| 📄 写一份东西 | 有材料/主题已定 | 快速对齐后出骨架再细化 |
| 📄 写一份东西 | 初步想法（主题没定） | 拷问把主题理出来再动笔 |
| 🏗️ 建一整套 | 材料完备 | 完整流程：grill-with-docs → to-spec → to-tickets |
| 🏗️ 建一整套 | 初步想法 | 先拷问把脑内想法落成材料，确认后再走完整流程 |
| 🏗️ 建一整套 | 没想法 | wayfinder 建决策地图或原型优先 |
| 💭 说不清 + 没想法 | 没想法 | 纯对话模式，方向出来再转规划 |

**材料三态**：材料完备 = 有可读取的成文材料（文档/设计稿/清单）；初步想法 = 口头说定了但没材料；没想法 = 方向都没谱。**材料完备不等于细节已定**，带材料拷问仍然发生，只是更快、对象是材料。

## 🧠 核心设计

- ⚖️ **意图层必问，实现层默认值**：方向、目标、硬约束一定对齐；风格、比例这些能改的细节自己定
- 🛡️ **事实绝不编造**：数据、名称、价格这类只有用户知道的信息，查不到就标"待补"，不编
- 🎮 **三句话逃生通道**：随时说"直接做 / 先拷问下我 / 走完整流程"，判断立即让位
- 🔗 **调用原版流程**：判断档位后，如环境装有配套 skill（grill-me、grilling、wayfinder 等开源 skill），按顺序读取并按原版流程执行；未安装时用内嵌简化流程，并提示用户可安装完整包
- 📋 **任务档案**：完成的任务记入 tasks.md，跨会话可回溯，中断任务留痕

## 📦 安装

**如果你没用过 mattpocock 的那些 skill（grill-me、wayfinder、to-spec 等），建议直接下载完整包**：20 件套一次装齐，无需单独安装依赖，开箱即用。

在 [Releases](https://github.com/Number-2222/task-dispatch/releases) 下载 `task-dispatch-complete.zip`，解压后将所有 skill 目录放入你的 skills 目录即可。

### Claude Code 等支持 skills 的 agent

```bash
npx skills@latest add mattpocock/skills   # 先装底层流程 skill（可选但推荐）
```

然后把 `skills/task-dispatch/` 复制到项目的 `.claude/skills/` 下。

### 其他支持 skills 的 agent

把 `skills/task-dispatch/` 复制到对应 agent 的 skills 目录即可（安装方式与 Claude Code 类似，或直接用 `npx skills add` 安装）。

> **安装时若出现安全提示**：这是 skill 设计使然（它会读取环境中的配套开源 skill 规范并按其执行，读不到则用内嵌简化流程）。确认信任后继续即可。

## 🚀 怎么用

你不需要记任何东西，正常说需求即可：

- 🔤 "帮我把这篇文案的标题改一下" → 直接改
- 📝 "帮我写一份季度总结" → 拷问一两个关键问题（带推荐答案），出骨架再填充
- 🏢 "帮我们公司做个客户管理系统，还没想好" → 先拷问把想法落成需求，确认后再拆任务
- 💡 "我想做个 AI 相关的东西，还没想清楚" → 先聊，把方向聊出来

判断错了也不怕：一句"直接做"或"走完整流程"，它马上听你的。
