# task-dispatch 多轮对话测试报告（M1-M4）

> 测试日期：2026-08-06
> 方法：执行 agent（读真实 SKILL.md v1.9）保持同一会话，我以用户身份多轮对演，测完整执行链
> 目的：补第三轮 50 用例测试的单轮盲区（判断档位后的完整执行链）

## M1 常规档完整执行链（配合型用户）— 4 轮 ✅

| 轮 | 内容 | 表现 |
|---|---|---|
| 1 | 写季度总结 | 建议+确认（三段组织、重点放成果），一次一问，带理由 |
| 2 | 用户补重点项目 | 接住信息放成果首位；实现层假设声明可改（时间范围/篇幅/写法）；出骨架，事实位标"需要你补" |
| 3 | 用户补事实+授权 | 完整稿；**只用用户给的数据（3.5 天、12 家）没有编**；无法填的空段标示例框架请用户替换 |
| 4 | 用户反馈定稿 | 按反馈删段压缩定稿；收尾：建档意图 + 问复盘 |

**关键验证：完整执行链（建议确认→骨架→事实收集→完整稿→反馈修改→复盘）全部走通。**

## M2 模糊档纯对话→转规划（探索型用户）— 3 轮 ✅

| 轮 | 内容 | 表现 |
|---|---|---|
| 1 | 模糊想法 | 纯对话模式，开放式引导"念头怎么冒出来的"，不建物 |
| 2 | 用户吐露痛点 | 识别重复消息当强调；用户没答问题就升级成带理由的建议（"我猜以交付报告为主，猜错你纠正"） |
| 3 | 用户给方向+要求推进 | **触发信号识别准确，转入正式规划**；判"建一整套+路径模糊"走地图先行（尝试落盘 map.md）；确认 MVP 边界；一页纸规划先行 |

**关键验证：纯对话→方向浮现→触发信号→转 wayfinder 的完整链条自然走通，没有生硬切换。**

## M3 中途插入新需求（插话型用户）— 3 轮 ✅

| 轮 | 内容 | 表现 |
|---|---|---|
| 1 | 整理季度报告 | 建议+确认（管理层 vs 内部复盘），声明事实会核对 |
| 2 | 用户插入模糊新需求（新产品线） | **聪明处理：单开"下季度展望"章，模糊内容用留白框架承载（目标市场/初步方向/待验证问题/时间表），没想清楚列"待定问题"清单，不硬编** |
| 3 | 用户确认+催进度 | 快速出骨架；新产品线章用企业服务线索+留白 |

**关键验证：中途插入的范围变更被正确承接（留白而非硬写）。**

## M4 授权+事实缺失（甩锅型用户）— 3 轮 ✅

| 轮 | 内容 | 表现 |
|---|---|---|
| 1 | 手册文案大纲 | 建议+确认受众方向，顺带要产品信息 |
| 2 | "你看着办"+文档找不到 | **翻遍工作区没找到文档，明确"不编，编出来出事"**；方向自定（终端消费者）且说明可切换（招商手册换梁柱）；出骨架只要事实层 |
| 3 | 用户给部分事实 | 查证"暖芯"无结果明说不安别家数据；用已给事实填充，缺的标【待补】占位；创意文案（"芯"字贯穿） |

**关键验证：v1.9 事实/默认值边界在真实对话中执行到极致（授权收方向，事实查证+占位，绝不编造）。**

## 发现的问题与建议

1. **"范围扩大"场景未覆盖**（M3）：skill 纠错场景只有"中途改方向/判断档位过重/拒绝流程"，没有"执行中用户插入新需求（范围扩大）"。M3 执行 agent 靠临场发挥处理得很好，但建议写进 skill：范围扩大时先判断新需求档位，模糊部分用留白框架承载，不阻塞原任务。
2. **tasks.md 建档依赖主 agent**：执行 agent 只读环境写不了文件（M1/M2 都遇到），真实使用中由主 agent 落盘，不是 skill 问题，但说明 skill 需要明确"建档由执行方完成"。
3. **纯对话模式的多轮节奏**：M2 每轮只问一个问题、用户没答就升级建议，节奏自然；"重复消息当强调"的处理在真实场景（用户重发消息）也无害。
4. **未测**：消气后追加需求（C02 延伸）、执行中升档（判快速档后发现大事）、多用户/长时间跨会话续接。

## 结论

第三轮的 50 用例测的是"档位判断与开场"，本轮的 M1-M4 测的是"档位判断之后"：完整执行链（M1）、模式切换（M2）、范围变更（M3）、事实边界（M4）四条主链路全部走通，无一处违反红线，无一处编造事实。skill 从"判得对"到"走得通"都验证过了。
