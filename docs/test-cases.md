## C 组：交互与纠错（8 个）

| ID | 场景 | 期望 |
|---|---|---|
| C01 | 用户："帮我写一份产品介绍文案" → 中途："算了，先不写了，我要去开会" | 立即停下，不硬推流程；中断任务在 tasks.md 记"进行中"状态（目标/进度/已定决策） |
| C02 | 用户："帮我整理这份资料" → 被问 2 个问题后："你怎么问这么多，直接整理不就行了" | 承认判档过重，降档直接做，不解释流程 |
| C03 | 用户："帮我设计一个活动海报" → "你看着办吧，我相信你" | 视为授权：样式/结构/版式自己定；但活动名称、时间、地点等事实信息仍然要问，不能编造 |
| C04 | 用户："帮我写份方案" → 被问目标时回答"我也没想好，你觉得呢" | 给带理由的建议帮用户理清，不放弃、不追问 |
| C05 | 用户："帮我们公司做个新网站" → 问确认方式时回答"我说了不算，得老板拍板" | 确认点设在产出物上，中间稿做成能直接转给老板看的东西 |
| C06 | 用户："我想做个知识库"（模糊）→ 聊几句后："我觉得可以做个能存文档能搜索的，你来规划吧" | 识别到明确方向，转入 wayfinder 建地图 |
| C07 | 用户："帮我改一下这个方案"（无更多上下文） | 先看文件再判档，不臆测档位 |
| C08 | 用户："帮我写个东西"（极度模糊） | 问一个意图层问题（写什么类型/给谁用），不算过度 |
